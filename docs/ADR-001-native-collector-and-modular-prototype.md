# ADR-001：0.2 使用原生 API 后端并拆分原型模块

- 状态：已采用
- 日期：2026-07-29
- 范围：原型可信化，不是最终商业架构

## 决策

0.2 使用 `psutil` 的 Windows 后端读取系统、磁盘和进程指标，移除高频
PowerShell/WMI 子进程。入口、采集、调度、内存快照和本地 HTTP 服务拆为
独立模块，以稳定 API 0.2 字段作为后续迁移边界。

调度采用单调时钟和绝对期限 \(t_k=t_0+kT\)。超过期限的旧周期被跳过并
记录，不通过“采集耗时 + sleep”累积漂移。

## 原因

- PowerShell 启动成本显著高于目标采样周期，并会进入被监控进程排行。
- WMI 格式化进程 CPU 是多核累计口径，直接显示会超过 100%。
- 单个全局可变字典无法为采样线程与 HTTP 请求提供一致快照。
- 明确模块边界后，可分别替换为 .NET 原生 Agent、IPC 与 SQLite，而无需
  继续扩大入口文件。

## 约束

- WMI 以后只允许用于低频硬件清单，不进入高频采样路径。
- 未取得的指标必须返回不可用状态，禁止填 0。
- HTTP 只监听回环地址；不因端口配置而默认开放远程访问。
- 需要管理员权限的未来动作必须进入独立 Broker，当前进程不申请管理员
  权限。

## 后续迁移

商业内核验证阶段把 `collector.py` 替换为 .NET LTS Agent，通过版本化 IPC
继续提供等价指标契约；RAM 只保留实时窗口，SQLite 保存聚合历史、告警和
动作审计。Python 原型在新内核通过正确性和 72 小时稳定性门禁后退役。
