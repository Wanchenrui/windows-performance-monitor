# v0.7.2 Broker threat model

## 范围和资产

范围包括 Desktop → Agent → Broker → Windows 的动作路径，以及 Broker
策略和审计库。监控 Provider、用户历史库和硬件 Worker不是 Broker 的
信任输入。

需要保护的资产：

- 其他用户和系统进程的完整性与可用性；
- 机器级电源配置；
- Broker 机器策略；
- 动作审计的完整性和可追溯性；
- Agent、Desktop 和实时采样的可用性。

## 攻击者

考虑以下攻击者：

1. 远程网络身份；
2. 同机其他普通用户；
3. 与 Agent 同 SID 的恶意普通进程；
4. 恶意或被攻陷的 Desktop；
5. 能发送损坏/超大/重复 IPC 的客户端；
6. 在动作期间触发目标进程退出、PID 复用或 Broker 崩溃的竞态。

已取得管理员或 LocalSystem 的攻击者不在权限提升防护范围内；该身份本来
就能修改 Broker 二进制、策略和系统状态，但其动作仍应尽可能留下审计。

## 信任边界

```text
[untrusted Desktop/request body]
       │ per-user pipe
       ▼
[Agent policy boundary]
       │ broker pipe; body still untrusted
       ▼
[transport SID/PID/image boundary]
       ▼
[Broker policy + target invariant boundary]
       ▼
[pending audit commit]
       ▼
[privileged OS executor]
```

任何上游批准都不能跳过下游校验。

## 威胁与控制

| 威胁 | 控制 | 剩余风险 |
|---|---|---|
| 网络客户端连接 Broker | Pipe DACL 显式拒绝 Network SID | Windows ACL/安装错误需在 v1.0 安装矩阵验证 |
| 其他用户修改目标进程 | 实际 Pipe SID；目标 owner SID 必须相等 | 机器级电源动作需额外机器策略批准 |
| 请求伪造 caller SID/PID | 身份字段禁止出现在 body；服务端从 Pipe 取得 | Named Pipe/令牌 API 失败时必须 fail closed |
| 同 SID 恶意进程直连 | Broker 从实际 Pipe PID 打开映像，解析最终路径并在文件锁内校验 SHA-256；service 模式还要求 WinVerifyTrust 可信链、Code Signing EKU、发布者 Subject、证书 SHA-256 以及固定 Program Files Agent 路径 | 运行期使用本机缓存而不联网做吊销查询；发布/更新链仍需阻止已撤销候选，便携/console 模式只 dry-run |
| PID 复用 | PID + creation ticks + owner SID 在临界区重验 | 目标可在最终状态读取前退出，结果需如实记录 |
| 任意代码执行 | 固定 action DTO；无 path/command/script/args/env/registry/GUID；首版 ID 仅映射到编译期实现 | 后续增加任何 approved ID 都必须重新做代码审查和签名门禁 |
| 重复请求 | caller-scoped idempotency 唯一键和请求摘要 | 崩溃窗口只能给出 indeterminate，不能证明成功/失败 |
| 审计绕过 | pending 提交成功后才执行；审计不可用 fail closed | OS 修改后终态提交失败会留下 indeterminate |
| DoS/内存耗尽 | 分配前帧上限、JSON/数组/字符串上限、连接/请求上限、串行 executor | 同机进程仍可造成有限连接压力；服务必须保持 accept loop 隔离 |
| Broker 故障拖垮监控 | Broker client 与 Provider/历史队列解耦，有限 deadline | 动作 capability 暂时不可用 |
| 敏感信息泄漏 | 不采集命令行；路径只保存哈希/受限标识；错误码稳定化 | 审计本身仍属敏感安全数据，导出需 v1.0 脱敏 |

## 安全不变量

以下条件必须由静态测试和运行测试共同冻结：

1. Broker 协议不存在任意命令、脚本、注册表或路径字段。
2. 请求体不能指定或覆盖 caller 身份。
3. 未持久化 `pending` 时 executor 调用次数恒为零。
4. `dryRun=true` 时 executor 的 mutation 调用次数恒为零。
5. Agent 或 Broker 任一策略拒绝时 mutation 调用次数恒为零。
6. 目标三元组不匹配时 mutation 调用次数恒为零。
7. 同一 caller/key 的 mutation 调用次数最多一次。
8. 启动发现 `pending` 只能转 `indeterminate`，不能转成功或自动重放。
9. Broker 不可用不得停止 Agent 采样、SQLite 写入或 Desktop 只读 IPC。

## v1.0 闭环状态

代码与进程级门禁已经完成：

- Broker 使用 `WinVerifyTrust/WINTRUST_ACTION_GENERIC_VERIFY_V2` 取得实际被
  信任的 Authenticode signer，额外要求显式 Code Signing EKU；机器策略
  同时固定 signer Subject 和 DER 证书 SHA-256。
- 客户端映像以只读、不允许写/删除共享的句柄保持稳定；同一句柄用于内容
  SHA-256 与 `WinVerifyTrust`，最终路径通过 `GetFinalPathNameByHandle` 解析，
  符号链接/重解析点不能把非产品映像伪装成
  `Program Files\PerfMonitor\agent\perf-monitor-agent.exe`。
- service 模式不可关闭 approved-image、可信签名或受保护路径门禁；启用任一
  动作时必须有且只有一个完整的 Agent 路径/文件哈希/签名者 pin。
- 运行期签名校验使用 cache-only URL retrieval，避免网络/吊销服务器延迟
  占住 Broker 客户端槽；证书撤销与候选禁用由签名发布和更新策略处理。
- 对抗测试覆盖固定与确定性畸形 framing 语料、超大/截断/无效 JSON、身份和
  命令字段注入、连接中止、并发重放冲突、签名内容篡改、发布者/证书/hash/
  路径错配、PID 复用、崩溃 pending 恢复和损坏审计库 fail closed。

仍需由签名 MSI/专用测试机提供的部署证据：

- Agent、Desktop、Broker 和安装包最终 Authenticode 生产签名；
- 服务账号、Broker 二进制路径、Pipe 与 ProgramData 策略/审计 ACL 的
  安装后检查；
- 标准用户、管理员过滤令牌、快速用户切换和多会话隔离；
- 安装、升级、受控回退和卸载时审计保留策略。
