## 1. 诊断解释与建议

把现有事件展开成“看到了什么 → 依据是什么 → 可能原因 → 可以怎么做”。先覆盖已有 CPU 繁忙、内存压力、磁盘空间不足等规则；沿用证据窗，明确缺测、陈旧与无法确定的条件。建议给出用户能执行的具体步骤，先只建议，不修改系统。高占用不能直接写成故障，规则置信度也不写成收益概率。

首版已接入可点选的诊断详情：保留简洁事件列表，只展开选中事件的必要证据和建议。

## 2. 进程与趋势交互

已有整机曲线、悬浮读数和进程排行，不重复建设。补上从排行选择单个进程、识别进程实例、查看已有指标与该实例 CPU 变化；复用现有曲线与抽屉。进程退出、PID 复用、缺测和隐藏期间的缺口须显示清楚，不能把不同实例的历史连起来。

首版已接入“点进程 → 看详情与变化 → 返回排行”，复用图形化布局。仅记录选中后收到的新观测，不回填选中前的历史；单实例缓存有数量、时间和字节上限。

**关注列表已补齐：**排行 / 详情可固定与取消，最多 12 条，只保留本次 Desktop 运行；绑定 Agent 会话、PID 与创建时间，不按名字接续重启后的实例。列表快速切换仍是单实例选中后记录趋势；旧会话 / 未观测 / 陈旧明确显示，不额外采集。刷新时保留同一按钮与焦点；普通固定、切换、取消及断连缺测已用真实窗口配模拟数据验证。抽屉与主曲线并排，最新端点可见，关闭后还原。

## 3. 软件自身可撤销轻量模式

先提供当前 Agent 会话内暂停 / 恢复 GPU 与温度请求的轻量开关。基础 CPU、内存、网络和磁盘采集保持原设置；已开始的硬件调用可继续完成，不承诺量化收益。保存修改前状态，恢复原采集状态；原值记录与恢复属于功能本身，不先建设通用租约框架。

首版已接入状态查询、开启和恢复入口；旧 Agent 不支持时不发送模式请求，连接变化或操作未确认时先刷新实际状态。

以后有明确需求，再增加用户逐项授权的可撤销动作。默认优化不包含终止进程、任意脚本或不受限的系统修改；高级场景自动化与扩展按实际使用需求再做。

## 已补齐：硬件采集恢复与帮助

电源关键状态未知时尝试 SystemBatteryState；GPU 负载缺测时尝试 Windows GPU Engine，首次预热与失败保持缺测，并受冷却限制。Worker 失败按现有启动预算恢复。质量抽屉按需展示实际尝试、原因和具体操作建议，不在界面额外采集。GPU 备用只给引擎负载，温度仍可能不可读；缺组不能推断未配置，无电池不是故障，驱动更新不保证温度支持。

末次真实窗口配模拟数据的键盘检查与后台截图已确认：单组帮助可展开，刷新后保留焦点，缺组说明清楚、换行无重叠。只读原生 API 探测验证本机电源状态和 GPU Engine 差分读数，不把它当作温度或正常 Agent / Worker 的完整联调。

## 日常只保留必要检查

每个功能保证能构建，运行与改动相关的回归；数据不乱、不丢、不越权，系统修改能恢复。纯展示小改不重复全量测试，不重新归档整套证据，也不每次重测全部资源。遇到性能或稳定性问题再做针对性测量。

真实 72 小时、四个目标 OS、生产签名 / SBOM、完整性能预算和安装器正式发布流程，均不再是个人功能开发前置。实际准备公开发布时，按发布对象与目标平台选做；目前未完成的项目继续标未验证。
