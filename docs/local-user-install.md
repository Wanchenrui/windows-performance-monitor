# 本机用户安装与真实体验

这是 PerfMonitor 1.1.0 开发候选的当前用户安装入口，使用真实 Agent、硬件 Worker 和 WPF Desktop。安装界面中的“安装”按钮会实际复制程序、创建快捷方式并登记卸载入口；没有模拟数据、模拟 IPC 或独立预览数据库。

## 自己体验完整流程

1. 双击安装包根目录的 `Install-PerfMonitor.cmd`，查看安装界面并点击安装。
2. 安装完成后点击“打开 PerfMonitor”。后续可从桌面或开始菜单打开。首次真实采集与连接需要几秒。
3. 在真实界面中查看本机 CPU、内存、磁盘、网络、进程及可读取的硬件信息；按需要体验关注进程、诊断、导出、通知与智能采样偏好。
4. 关闭窗口会进入托盘驻留。从托盘菜单退出会结束 Desktop；Agent 继续后台采集，这是当前产品的独立生命周期。
5. 卸载可使用 Windows“应用和功能”中的“PerfMonitor（开发候选）”入口。卸载前会确认，结束本安装的进程并移除程序和快捷方式，保留数据和日志。

程序安装到 `%LOCALAPPDATA%\Programs\PerfMonitor`，使用标准数据目录 `%LOCALAPPDATA%\PerfMonitor\data`。启动日志写入 `%LOCALAPPDATA%\PerfMonitor\logs`。历史数据不会被主动清除；真实 Agent 会按现有产品规则打开及维护正式数据目录。

包内附带 .NET 10.0.10 运行时，不依赖开发 SDK 路径，也不改全局运行时。附带运行时只是应用部署方式，采集仍直接来自本机。安装只面向当前用户，不要求提权，不自动创建开机启动，不安装或启动 Broker。

## 仍存在的边界

- 这是新增的本地候选安装入口，不是原 WiX MSI，也不是已签名发布版本。尚未覆盖安装升级、OS 矩阵或长时间运行验证。
- 原 MSI 的客户端安装条件不接受 Windows 10，且缺少安装完成后的首次 Agent 启动衔接；这些原 MSI 问题没有被此入口验证或消除。当前本机入口用于 Windows 10 上的开发候选体验，不代表新增正式 OS 支持承诺。
- 现成 Release 输出直接打包，不重复构建或运行测试。不同组件的文件版本与原构建时间保存在包内 `package-info.json`，不能视作一次新的统一发布构建。
- 普通权限下，实际温度或部分传感器可能不可读。界面展示真实质量状态；GPU Engine 备用只能提供负载，不能提供温度。尚未确认本机完整 Agent/Worker 链路的实际结果。
- 未安装 Broker 时，依赖 Broker 的特权动作不可用。智能采样调节的是监控软件自己的采集开销，不能据此宣称已经优化了其他应用或提升整机性能。
- 用户已明确允许本次真实运行使用产品原有的诊断和持久化 SHA-256 指纹。打包与安装脚本不额外计算文件哈希。

## 开发者准备入口

使用 `scripts/prepare-local-user-installer.ps1` 复制现成 Release 输出、安装脚本及既有运行时，生成一个新的 `artifacts/local-user-installer-*` 目录。准备入口不运行应用、测试、发布签名或文件哈希，也不覆盖旧包。
