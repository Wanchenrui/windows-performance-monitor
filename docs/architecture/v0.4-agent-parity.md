# 0.4 Agent 指标对齐架构

## 结论

0.4 在冻结的 contract v1 之后旁路引入 `.NET 10` Agent。Python 0.3
不再扩建，而是只读 oracle。Agent 仍是模块化单体，不引入 Desktop、
SQLite、Named Pipe、GPU SDK 或特权动作。

## 依赖与数据流

```text
PerfMonitor.Contracts
        ↑
PerfMonitor.Core
        ↑
Collectors.Windows ──→ ProviderScheduler
                              ↓
                       SnapshotAssembler
                              ↓
                       AtomicSnapshotCache
                              ↓
                      Agent JSONL 验证出口
```

`Core` 不引用 Win32、SQLite、UI 或具体 IPC。Windows 调用只存在于
`Collectors.Windows`。

## Provider 周期与时序

| Provider | 周期 | 超时 |
|---|---:|---:|
| System CPU | 1 s | 750 ms |
| Memory | 1 s | 500 ms |
| Uptime | 1 s | 250 ms |
| Agent self metrics | 1 s | 500 ms |
| Processes | 2 s | 1,500 ms |
| Volume capacity | 30 s | 5 s |

Provider \(i\) 的期限保持为绝对序列：

\[
d_{i,k}=d_{i,0}+kT_i
\]

采集结束后从前一期限推进到第一个严格晚于当前单调时钟的期限，不使用
“执行时间 + sleep”。连续失败的有效周期乘数为
\(\min(2^f,8)\)。同一 Provider 上一任务未结束时不创建第二任务，只发布
该组 timeout/busy 证据；全局并发由有界信号量限制。

## 指标物理口径

系统 CPU 使用两次 `GetSystemTimes` 的差分：

\[
U_{sys}=100\%
\left(
1-\frac{\Delta Idle}
{\Delta Kernel+\Delta User}
\right)
\]

Windows 的 `Kernel` 已包含 `Idle`，因此分母不能再次加 Idle。

进程 CPU 使用：

\[
U_{core}=100\%\frac{\Delta CPUTime_p}{\Delta t},
\qquad
U_{norm}=\frac{U_{core}}{N_{logical}}
\]

进程差分键为 `(PID, creationTimeTicks)`。PID 0 是 Idle 伪进程，不计入
enumerated/readable/skipped；受保护或瞬间退出的普通进程必须使用稳定错误
码进入覆盖率，不能伪造为 0。

## 故障与资源边界

- 每个 Provider 的异常只更新对应组。
- Snapshot 发布使用完整新对象，读者不会混读两个批次。
- `--quiet` 只关闭控制台副本；指定 `--output` 时仍写入有界频率的 JSONL。
- `compare_agents.ps1` 采用一对一最近时间配对，CPU/内存只对同窗聚合门禁，
  同时精确检查单位、source ID、卷总容量、空值和进程身份。
- `run_agent_soak.ps1` 默认运行 259,200 秒，门禁 working set、private
  memory、首尾稳态增长和 GC heap 增长。

CI 的短时真实资源门禁用于尽早发现退出、句柄、序列和明显增长问题；
`SoakSimulationTests` 快速覆盖 259,200 个期限与 259,200 次快照替换。
二者都不冒充真实 72 小时墙钟证据。

## 回退

0.4 没有数据库、IPC 或安装数据迁移。运行时回退点为 `v0.3.0` Python
oracle 标签。
