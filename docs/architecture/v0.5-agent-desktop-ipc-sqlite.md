# v0.5 Agent / Desktop / IPC / SQLite 实现说明

## 目标

v0.5 把采样生命周期、UI 生命周期和持久化 I/O 解耦。核心不变量是：

1. Desktop 退出不能停止采样；
2. SQLite 变慢或失败不能改变 Provider deadline；
3. 慢 IPC 客户端不能形成无界队列；
4. 不同 Windows 用户不能连接到同一 Agent；
5. 所有历史查询在进入 SQL 前有绝对范围与点数上限。

## 时序与背压

Provider scheduler 继续使用 v0.4 的独立绝对期限。Agent 的快照发布循环默认
每 1 秒读取一次 `SnapshotAssembler` 的不可变引用，然后依次调用消费者的
`TryPublish`：

```text
t = k seconds
  assembler.Read()                  O(1) 引用读取
  storage.TryPublish(snapshot)      无等待；容量 256
  subscriptions.TryPublish(...)    无等待；每订阅容量 1
  optional JSONL validation output  不在 Provider 执行线程
```

`SnapshotFanout` 不等待磁盘、Pipe 或客户端。存储队列满时当前样本被丢弃并
增加 `droppedPersistenceSamples`；订阅队列满时覆盖旧快照。因此下游最坏
阻塞时间不进入 Provider 的控制周期。

SQLite writer 是唯一 reader，每次最多取 64 个快照并在单事务中写 raw 与
分钟/小时 rollup。查询使用独立只读连接和 1 秒 `busy_timeout`。这保证写锁
竞争有有限上界，但不承诺磁盘故障时不丢历史；实时快照优先于持久化完整性。

## 进程与信任边界

```text
current user
  PerfMonitor.Agent (non-elevated)
     protected Named Pipe DACL
  PerfMonitor.Desktop (non-elevated)

LocalSystem
  reserved for future Broker integration; no v0.5 action endpoint
```

实际 Pipe 名为 `PerfMonitor.<SID>.agent`。DACL 禁止继承、拒绝 Network，
只允许该 SID 与 LocalSystem。`FirstPipeInstance` 防止 Agent 静默连接到
预先创建的同名对象。v0.5 IPC DTO 不包含命令行、PowerShell、脚本或任意
文件/注册表路径。

## 协议状态机

```text
connect
  -> hello within 5 s
  -> negotiate contract 1.0 and <= 4 MiB message size
  -> sequential requests or one active subscription
  -> disconnect cancels subscription
```

Desktop 为每条连接串行化请求，避免响应乱序。实时会话断开后保留最后快照，
每 1 秒重试；新 hello 的 `instanceId` 与上一实例不同则
`RestartCount += 1`。历史按钮另建短连接并固定请求最近 24 小时、最多
240 个桶。

## 历史层级

| 查询跨度 | SQL 数据源 |
|---|---|
| ≤ 24 小时 | raw |
| > 24 小时且 ≤ 30 天 | 1 分钟 rollup |
| > 30 天且 ≤ 366 天 | 1 小时 rollup |

SQL 根据 `ceil(range / maxPoints)` 计算输出桶，并聚合
`min/max/avg/last`。`last` 按样本时间和 sequence 排序，`max` 保留短时
尖峰。输出桶数量不超过 `maxPoints`，不会先把全量源点读入托管内存。

## 故障矩阵

| 故障 | 实时快照 | 历史 | Desktop |
|---|---|---|---|
| 单个 Provider 超时 | 其他组继续；该组降级 | 写入当前质量状态 | 显示部分/陈旧 |
| SQLite 初始化失败 | 继续 | `service_unavailable` | 实时仍连接 |
| SQLite 运行写失败 | 继续，累计丢弃 | 已有库可只读时继续 | 历史提示不可用 |
| Desktop 退出/崩溃 | 继续 | 继续写入 | 下次启动重连 |
| Agent 重启 | 中断后恢复 | 同一用户 DB 复用 | 识别新 instance ID |
| IPC 恶意长度 | 不受影响 | 不执行查询 | 连接被关闭 |

## Python 退役与回退

默认启动、构建和 CI 发布物只包含 .NET Agent/Desktop。Python 0.3 只在
测试、差分和显式开发 HTTP 模式运行。回退 v0.4 时保留 schema v1 数据库；
v0.4 不读取该文件，重新升级后可继续使用。任何 migration 故障都不得通过
静默删除数据库“修复”。
