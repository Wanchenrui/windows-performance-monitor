# v0.7.1 隔离硬件 Provider Worker

## 进程与依赖

```text
PerfMonitor.Agent
  ├─ PerfMonitor.Collectors.Windows
  ├─ PerfMonitor.Collectors.Worker
  │    └─ PerfMonitor.ProviderWorker.Protocol
  └─ 固定子进程
       └─ PerfMonitor.ProviderWorker
            ├─ PerfMonitor.ProviderWorker.Protocol
            └─ LibreHardwareMonitorLib 0.9.6
```

`PerfMonitor.Agent`、`PerfMonitor.Core` 与
`PerfMonitor.Collectors.Windows` 的引用闭包中不得出现
`LibreHardwareMonitorLib`。第三方硬件代码只在 Worker 进程内加载。

## 一次采集

```text
gpu Provider ───────┐
                    ├─ 250 ms 合并窗口
sensors Provider ───┘
          │
          ▼
HardwareWorkerClient（串行）
          │  requestId + collect
          ▼
固定 Worker 子进程
          │  instanceId + sequence + bounded readings
          ▼
协议/范围校验
          ├─ gpu ProviderResult
          └─ sensors ProviderResult
```

两个 Provider 仍由独立绝对期限调度，Worker 协调器只复用同一时刻的
底层硬件快照。合并不会改变各 Provider 的完成时间、超时、freshness 或
错误状态。

两个组的默认周期为 5 秒，超时为 10 秒，以容纳首次硬件枚举。Agent
默认并发为 5：两个硬件调用即使等待同一 Worker，也不会占用原有核心
Provider 的 3 个并发槽；Worker 进程内部始终只有一个采集请求。

## 故障状态机

```text
未启动
  ├─ Worker 缺失 ───────────────► not_supported
  ├─ 重启预算耗尽 ──────────────► resource_exhausted
  └─ 启动成功
       ├─ 正常响应 ─────────────► available / partial
       ├─ 无对应硬件 ───────────► not_supported
       ├─ 权限不足 ─────────────► permission_denied / partial
       ├─ 超时 ─► 终止进程树 ───► timeout
       ├─ 崩溃 ─► 丢弃会话 ─────► unavailable
       ├─ 超大/损坏帧 ─► 终止 ──► invalid_data
       └─ 超内存 ─► 终止 ───────► resource_exhausted
```

任何分支都只更新 `gpu`/`sensors` 结果。核心采集调度器、实时快照、
SQLite 单写者和 IPC 不等待 Worker 恢复。

Agent 在边界上要求 coverage 满足
`readable + skipped = enumerated`，并把没有目标传感器的已枚举硬件计入
`skipped`。Worker 时间戳不参与 freshness；时间语义取自 Agent 自己的
调度上下文。

## 物理口径

设一次 Worker 响应中可读 GPU load 集合为
\(\mathcal{L}=\{l_1,\ldots,l_n\}\)，温度集合为
\(\mathcal{T}=\{t_1,\ldots,t_m\}\)。聚合定义为：

\[
L_{\max} =
\begin{cases}
\max \mathcal{L}, & n>0\\
\mathrm{null}, & n=0
\end{cases}
\qquad
T_{\max} =
\begin{cases}
\max \mathcal{T}, & m>0\\
\mathrm{null}, & m=0
\end{cases}
\]

其中 \(0\le l_i\le100\)，温度仅接受
\(-100\le t_i\le250\ ^\circ\mathrm{C}\) 的有限数。范围用于拒绝驱动
哨兵值和损坏协议，不表示产品认可该温度为安全工作点。

不同 GPU/传感器的读数没有可相加的物理意义，因此不提供 sum。

## 验收门槛

- 固定协议的正常、截断、超大与损坏帧测试；
- 利用率和温度聚合口径测试；
- Worker 缺失、崩溃、超时、重启预算与内存超限测试；
- 同次采集复用及并发串行测试；
- 发布后的真实 Worker 协议冒烟，即使 CI 主机无 GPU；
- Agent 快照必须同时包含 `gpu` 与 `sensors`，但允许明确
  `not_supported`；
- 构建产物必须包含 Worker、锁文件哈希和第三方许可清单；
- 静态门槛禁止 Agent/Core/Windows Collector 直接引用硬件库。
